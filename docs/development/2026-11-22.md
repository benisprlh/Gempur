## Perubahan dan batas

Sebelumnya kegagalan request inbox temuan masuk ke backoff layanan yang sama dengan dashboard, sehingga bantuan berikutnya bisa tertunda sampai lima menit walaupun dashboard sehat. Kini dashboard/bantuan/koreksi tetap diproses sebelum gate retry inbox. Network/5xx memakai30/60/120/240/300s,4xx/429 lima menit, per instance layanan memakai elapsedRealtime. Hanya fetch inbox berhasil mereset retry; dashboard sehat tidak meresetnya.401 tetap diteruskan untuk penghentian sesi.

Pemeriksaan stop/akun/pasangan sebelum/sesudah request tetap ada. Vault/notification exceptions berada di luar catch fetch; dedup setelah OS request bukan delivered/read. Consent/epoch/antrean/grant/AI dan cooldown notifikasi60s tidak diubah. Worker tunggal dan timeout jaringan tetap: request lambat, dashboard gagal, rate limit global atau lifecycle dapat menunda siklus. Tidak menjanjikan push atau tepat30s.

- [AWS retry guidance](https://docs.aws.amazon.com/wellarchitected/latest/framework/rel05-bp03.html) membahas pemisahan dependency, pembatasan dan klasifikasi kegagalan. Patch mengisolasi retry GET inbox, tanpa nested retry atau antrean tambahan. Jitter/max-attempt budget lebih lanjut masih backlog; bukan klaim seluruh panduan telah diterapkan.
- [Android TaskManager](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping) tetap mengharuskan batas lifecycle dipahami. Recovery consent PR15 tetap; belum ada uji HP/emulator.
- [Play VPN](https://support.google.com/googleplay/android-developer/answer/12564964?hl=en): disclosure/consent serta evaluasi build biasa tetap gate. Privat bukan approval Play/Play Protect.
- [OWASP mobile testing](https://mas.owasp.org/MASTG/0x04b-Mobile-App-Security-Testing/) memisahkan perilaku aplikasi, penyimpanan dan trafik; unit policy tidak membuktikan transport/perangkat.
